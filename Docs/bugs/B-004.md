# Bug B-004: Simulator readiness can accept failed data migration

## Summary

The authoritative full quality gate can continue into UI testing after `simctl bootstatus` reports a terminal simulator data-migration failure. The first Xcode UI-automation launch can then time out even though the remaining tests pass after the simulator recovers.

## Status

Resolved.

## Priority

P1. The defect makes the authoritative hosted gate depend on an invalid simulator-readiness result and blocks trustworthy completion evidence.

## Objective

Make the shared simulator-readiness gate reject terminal boot or data-migration failure even when `simctl bootstatus` exits successfully, and permanently guard that behavior.

## Non-goals

- Retrying failed UI tests, simulator boots, or application launches.
- Increasing XCTest, simulator, or application-launch timeouts.
- Suppressing failures or treating a red hosted run as completion evidence.
- Changing Cadence product behavior, persistence, accessibility, or user-facing copy.
- Starting F-005 implementation.

## Workflow

- Tier: 3.
- Rationale: the correction changes the authoritative local and hosted build gate. Accepting an invalid readiness state could create recurring false starts or undermine release confidence.

## Acceptance notes

- The readiness helper still resolves and waits for the selected simulator without retrying.
- A nonzero `bootstatus` exit fails readiness as before.
- A zero exit is accepted only when the final terminal stanza reports `isTerminal=YES` followed by `Finished`; terminal failure, missing-terminal, empty, and malformed output fail closed with retained diagnostics.
- A deterministic negative fixture reproduces the observed zero-exit terminal-failure state.
- The policy suite, fast gate, and authoritative full gate pass locally.
- Independent Tier 3 planning and complete-diff reviews find no unresolved high or critical issue.
- A hosted full gate must pass before B-004 is resolved.

## Observed behavior

GitHub Actions run `42420186606` recorded `Status=3, isTerminal=YES` and `Data Migration Failed` in `simulator-readiness.log`, but `Scripts/prepare-simulator.sh` continued because `simctl bootstatus` returned zero. Xcode subsequently timed out connecting to the cloned simulator's lockdown service, and `testAppLaunchesWithMyDaySelected` failed after 277.404 seconds while launching Cadence. The remaining 19 UI tests passed after the simulator recovered.

## Expected behavior

The shared readiness helper must accept only a successful terminal simulator state. A terminal migration or boot failure must stop the gate before build or UI-test execution and preserve the readiness log for diagnosis.

## Investigation notes

- The failure precedes application interaction and does not implicate Cadence startup behavior.
- B-003's explicit cross-test application cleanup remains effective; every subsequent UI test passed.
- B-002 established `simctl bootstatus -b`, but its behavioral fixture covered only process exit status. Run `42420186606` proves that exit status alone does not express the complete readiness contract.
- Xcode tested on a simulator clone after the selected base device's migration failure. This correction guards the earliest deterministic invalid state; it does not claim direct control over Xcode's private clone lifecycle.

## Validation plan

- Add a readiness-log validator that accepts only a final terminal `Finished` state and rejects every other outcome.
- Extend the fake-`xcrun` fixture with a zero-exit `Data Migration Failed` example and prove the helper rejects it.
- Retain the existing nonzero-exit fixture and successful behavior check.
- Run `Scripts/check-policy.sh`, `Scripts/quality.sh --fast`, and the authoritative `Scripts/quality.sh`.
- Obtain independent architecture, implementation/UX, test, and complete-diff review.
- Require a successful immutable hosted run before resolution.

Resolved by revisions `61632dbeb9d070b747ef49ba5bc9922e18e85226` and `cca0eaf5cc318fdd001fdefbd84ad2d581d92d27`.
