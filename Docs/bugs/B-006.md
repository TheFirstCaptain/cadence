# Bug B-006: Hosted Day History back navigation query fails on iOS 27.2

## Summary

Two History UI tests query the first button inside the navigation bar to return from Day detail. On the hosted iOS 27.2 simulator, XCTest exposes the system back control as a `Button` with identifier `BackButton` elsewhere in the accessibility hierarchy while the navigation-bar descendant query computes it as `Other`. Both tests therefore fail before exercising their return-navigation assertions.

## Status

Validating.

## Priority

P1. The compatibility defect blocks the authoritative hosted quality gate even though the app behavior and all unit tests pass.

## Objective

Use one stable UI-test helper that locates the system back control by accessibility identity without depending on its hierarchy parent or computed element type.

## Non-goals

- Changing Cadence navigation or user-facing behavior.
- Adding a custom back button to production UI.
- Retrying failed UI tests or weakening assertions.
- Increasing timeouts or suppressing simulator failures.
- Treating the separate hosted lockdown timeouts as fixed by this change.

## Workflow

- Tier: 1.
- Rationale: this is a narrow UI-test compatibility correction with no product, persistence, date, privacy, dependency, or destructive-action impact.

## Acceptance notes

- Both affected tests use the same helper to locate `BackButton` across the application hierarchy.
- The helper waits for the control, fails with a focused diagnostic if it is unavailable, and taps only after successful discovery.
- The tests still prove that returning from Day detail preserves the selected Week.
- Focused affected tests and the authoritative quality gate pass locally.
- Static policy and a representative negative fixture reject positional navigation-bar button queries anywhere in the UI-test target.
- An independent complete-diff review finds no unresolved high or critical issue.
- A hosted authoritative run passes before resolution.

## Observed behavior

GitHub Actions run `43968312871` for revision `1c60acfb65c6b1212637817057c6daca30da9680` passed all 115 unit tests and 26 of 28 UI tests. `testHistoryDayDetailIsReadOnlyAndReturnsToSelectedWeek` failed at line 134 and `testHistorySwitchesToMonthAndDrillsIntoACompleteWeek` failed at line 74 when `app.navigationBars.buttons.element(boundBy: 0)` found no matching button.

## Expected behavior

The UI tests should locate and activate the visible system back control without relying on XCTest assigning the same element type through both legacy and modern accessibility representations.

## Reproduction or confirmation

1. Run the authoritative quality gate on the hosted iPhone Duo simulator with iOS 27.2.
2. Open Day History in either affected test.
3. Observe the navigation-bar button query fail with `Automation type mismatch: computed Other from legacy attributes vs Button from modern attribute`.
4. Inspect the retained hierarchy and observe a `Button` identified as `BackButton` outside the navigation bar's descendant tree.

## Investigation notes

- The retained `Tests.xcresult` confirms the same XCTest compatibility failure in both tests.
- The visible Day detail loaded successfully before each failure; this is not an F-005C or F-005D product-state failure.
- The hosted runner also recorded two 120-second lockdown connection timeouts earlier in the run. Those did not cause these two assertion failures and remain outside this bug's scope.
- Querying `BackButton` through `app.descendants(matching: .any)` follows the stable identifier visible in the failure hierarchy while avoiding both the unstable parent relationship and element-type mismatch.

## Validation plan

- Replace both direct navigation-bar queries with one `navigateBack(in:)` helper.
- Have the helper query the application hierarchy by exact `BackButton` identifier and require existence before tapping.
- Add static policy and a negative fixture that reject positional navigation-bar button queries in UI tests.
- Run both affected UI tests together on the prepared simulator.
- Run `Scripts/quality.sh --fast`, then the authoritative `Scripts/quality.sh` after review.
- Require a successful immutable hosted run before resolving the bug.
