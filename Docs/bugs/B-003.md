# Bug B-003: Hosted UI tests can retain the app between cases

## Summary

The authoritative hosted quality run can fail before a UI test begins because XCTest cannot terminate the Cadence process left running by the preceding test case. This blocks trustworthy F-004 completion evidence even though the affected My Goals workflow and the remaining automated tests pass.

## Status

Resolved.

## Priority

P1. The failure blocks the authoritative hosted gate and therefore blocks F-004 closeout.

## Objective

Give every UI test an explicit, test-owned application lifecycle so a completed case does not leave Cadence running for the next case, and permanently guard that lifecycle contract.

## Non-goals

- Retrying failed UI tests or relaxing timeouts.
- Weakening result-bundle verification or allowing a failed hosted run to count as evidence.
- Changing My Goals product behavior, persistence, or user-facing copy.
- Starting F-005 History implementation.

## Workflow

- Tier: 3.
- Rationale: the correction changes the hosted/local UI-test execution contract and the authoritative completion gate. A false green or recurring process-lifecycle failure would undermine release confidence.

## Acceptance notes

- Every UI test launches Cadence through one lifecycle helper.
- The lifecycle helper registers explicit application termination for test teardown.
- Tests that intentionally terminate and relaunch the application remain supported.
- A deterministic negative fixture rejects removal or bypass of the shared lifecycle contract.
- The focused UI suite and authoritative local full gate pass.
- A hosted full gate passes on the committed correction before B-003 and F-004 close.
- No retry, timeout increase, or failure suppression is introduced.

## Observed behavior

GitHub Actions run `41945391613` failed `testMyGoalsRemovalExplainsHistoryAndCanCancelOrConfirm` before its first interaction. XCTest spent approximately 66 seconds trying to terminate `com.kirkgartside.cadence:26924`, which had been launched by the preceding `testMyGoalsReadFailureOffersCalmRetry`, then reported `Failed to terminate`. The other UI tests continued and passed, and the unit suite passed.

## Expected behavior

Each UI test owns and cleans up its launched Cadence process so the next case starts without depending on XCTest's implicit cross-case process cleanup.

## Reproduction or confirmation

1. Inspect immutable GitHub Actions run `41945391613` for revision `0b11874479ae5e008f0a654d26966122271fe2fc`.
2. In `Tests.xcresult`, observe that `testMyGoalsReadFailureOffersCalmRetry` passes and that process `26924`, which it launched, is still running when the next test begins.
3. Observe that the next test fails during `XCUIApplication.launch()` while trying to terminate that process, before the removal workflow executes.
4. Observe that subsequent UI tests and all unit tests pass, isolating the failure to cross-test application lifecycle cleanup rather than the My Goals removal behavior.

## Investigation notes

- Hosted environment: Xcode 27.1, iPhone Duo simulator, iOS 27.1.
- The shared quality path already resolves, boots, and waits for the simulator before the suite. Simulator readiness succeeded.
- The failure occurred between two tests after more than a dozen prior UI cases passed, so cold-boot readiness is not the failing class.
- Before the correction, each test created a local `XCUIApplication`, called `launch()`, and relied on XCTest to terminate it when the following test launched. Only one test explicitly terminated for an intentional relaunch.
- The lowest-cost correction is a shared launch helper that immediately registers test teardown termination, plus a static policy and negative fixture preventing direct unmanaged launches.
- Product data is test-fixture data in an isolated UI-test process. No production data or persistence behavior is implicated.

## Resolution

Resolved by revision `7d963e26b2fe096bc252d655bda6a00c9147d20f`. Every UI test now launches Cadence through one helper that registers explicit teardown termination before launch. Local and hosted full gates passed without retries, timeout changes, or failure suppression.
