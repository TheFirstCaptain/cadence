# Bug B-005: Hosted test clones can lose simulator services

## Summary

The authoritative hosted quality gate can move the complete test run onto an Xcode-created private simulator clone that is not reachable through the lockdown service, even after the selected base simulator reports successful readiness. The first UI test then fails during application cleanup while the remaining tests pass after the clone recovers.

## Status

Resolved.

## Priority

P1. The defect makes the authoritative hosted gate depend on an unvalidated private simulator clone and blocks trustworthy completion evidence.

## Objective

Keep the authoritative test run on the explicitly resolved and validated simulator destination, and permanently guard the shared scheme against execution settings that reintroduce dependence on Xcode-created test clones.

## Non-goals

- Retrying failed UI tests, simulator boots, application launches, or hosted jobs.
- Increasing XCTest, simulator, application-launch, or workflow timeouts.
- Suppressing teardown failures or accepting a red hosted run as completion evidence.
- Removing test-owned application cleanup established by B-003.
- Changing Cadence product behavior, persistence, accessibility, or user-facing copy.
- Starting F-005 implementation.

## Workflow

- Tier: 3.
- Rationale: the correction changes the authoritative local and hosted test-execution contract. Dependence on an unhealthy private clone can make the release gate fail nondeterministically or encourage unsafe failure suppression.

## Acceptance notes

- The full gate resolves, validates, and executes tests on one explicit simulator destination without Xcode-created execution clones.
- Unit and UI tests retain their existing coverage and fail normally when their assertions or cleanup fail.
- A deterministic negative fixture rejects scheme configuration that permits parallel test execution.
- The policy suite, fast gate, and authoritative full gate pass locally.
- Independent Tier 3 planning and complete-diff reviews find no unresolved high or critical issue.
- A hosted full gate passes before B-005 is resolved or B-004 uses the run as completion evidence.
- No retry, timeout increase, or failure suppression is introduced.

## Observed behavior

GitHub Actions run `42486107866` for revision `61632dbeb9d070b747ef49ba5bc9922e18e85226` recorded a successful terminal `Finished` state for the selected iPhone Duo simulator. Xcode then ran tests on `Clone 1 of iPhone Duo`, which timed out twice connecting to `com.apple.instruments.deviceservice.lockdown`. `testAppLaunchesWithMyDaySelected` failed during its registered teardown because `XCUIApplication.terminate()` could not reach the clone. The other 19 UI tests and all unit tests passed after the clone recovered.

## Expected behavior

The authoritative gate should execute its complete test suite on the same explicitly selected simulator whose readiness it validates, without introducing an unvalidated private execution clone.

## Investigation notes

- The base simulator took 102 seconds to boot and migrate, then reported the exact successful terminal outcome required by B-004.
- The failure occurred later on an Xcode-created iOS 27.2 clone and therefore does not disprove the B-004 readiness validator.
- The first UI scenario reached teardown; the recorded failure is infrastructure communication during `app.terminate()`, not a Cadence assertion or startup-state failure.
- The shared Cadence scheme previously marked the unit-test bundle parallelizable. Xcode can satisfy parallel test execution by cloning the simulator destination, which moves even nonparallel UI execution onto a private clone outside the readiness helper's ownership.
- B-003's test-owned teardown remains correct: a cleanup communication failure must stay visible rather than be ignored.

## Validation plan

- Remove parallel test execution from the authoritative shared scheme while preserving build parallelization and the focused fast scheme's parallel unit-test behavior.
- Pass `-parallel-testing-enabled NO` directly to the full gate's test invocation so the executable contract does not rely on scheme metadata alone.
- Add static policy for both the full invocation and complete shared scheme's nonparallel execution contract.
- Add representative negative fixtures proving that command-level or scheme-level parallel test execution is rejected.
- Run `Scripts/check-policy.sh`, `Scripts/quality.sh --fast`, and the authoritative `Scripts/quality.sh`.
- Confirm full-gate runtime evidence names the selected simulator rather than an Xcode-created clone.
- Obtain independent architecture, implementation/UX, test, and complete-diff review.
- Require a successful immutable hosted run before resolution.

## Resolution

Resolved by revision `cca0eaf5cc318fdd001fdefbd84ad2d581d92d27`. The authoritative shared scheme is nonparallel and the full quality invocation explicitly disables parallel test execution, keeping the suite on the prepared simulator. Static policy and independent negative fixtures reject either configuration layer reintroducing clone dependence; local and hosted full gates passed without retries, timeout changes, or cleanup suppression.
