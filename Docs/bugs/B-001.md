# Bug B-001: Hosted quality run masked UI test failures

## Summary

The hosted full quality job concluded successfully even though its Xcode result bundle recorded two failed F-002 UI smoke tests.

## Objective

Make the authoritative quality gate independently reject any test result bundle that records failures, a non-passing result, or no executed tests, even when `xcodebuild` returns success.

## Non-goals

- Changing application behavior or persistence.
- Hiding, retrying, or weakening flaky UI tests.
- Replacing Xcode result bundles or adding a third-party test reporter.

## Acceptance notes

- The production result-bundle wrapper extracts the supported `xcresulttool` test summary from `Tests.xcresult`.
- Verification requires `result` to equal `Passed`, `failedTests` to equal zero, `testFailures` to be empty, and `totalTestCount` to be greater than zero.
- A negative summary fixture proves recorded failures are rejected.
- A policy fixture proves the production wrapper cannot silently stop enforcing the extracted summary.
- Local and hosted full gates use the same verification path.

## Workflow

- Tier: 3.
- Rationale: The defect allows CI to misrepresent failing persistence, calendar, privacy, accessibility, or other high-risk tests as a successful authoritative gate.

## Status

Validating.

## Priority

P1.

## Observed behavior

GitHub Actions run `40857169892` completed successfully for source revision `17b79af4b0b526eecaca34b5a91d32a0309f8499`, but the log and `Tests.xcresult` reported failures in the default-tab and primary-tab navigation tests. Xcode 27.1 returned a successful process status after continuing to Swift Testing, and the repository verifier checked only that result-bundle directories existed.

## Expected behavior

The authoritative quality gate must fail whenever the test result bundle reports a non-passing result, any failed test, or no executed tests, regardless of the `xcodebuild` process status.

## Reproduction or confirmation

1. Inspect GitHub Actions run `40857169892` for commit `17b79af4b0b526eecaca34b5a91d32a0309f8499`.
2. Observe `** TEST EXECUTE FAILED **` and two named UI-test failures in the log.
3. Observe that the job nevertheless concluded successfully.

## Investigation notes

The defect is in completion verification, not app data or persistence. `Scripts/verify-result-bundles.sh` verified existence only and trusted `xcodebuild`'s status. The correction parses the supported `xcresulttool get test-results summary` output and independently enforces a passed result, zero failures, and at least one executed test.

## Validation plan

- Add a negative fixture proving a failed summary is rejected and a wiring fixture protecting the production verification path.
- Run the repository policy fixture suite.

- Push the correction and require a new successful hosted full-gate run before resolving the bug or closing F-002.
