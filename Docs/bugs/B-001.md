# Bug B-001: Hosted quality run masked UI test failures

## Summary

Two hosted full quality jobs concluded successfully despite the same two failed F-002 UI smoke tests: the first lacked result verification, while the second masked the quality script's unsuccessful exit through its logging pipeline.

## Objective

Make the authoritative quality gate independently reject failed test result bundles and ensure the hosted workflow propagates any quality-script failure through its logging pipeline while retaining uploadable evidence.

## Non-goals

- Changing application behavior or persistence.
- Hiding, retrying, or weakening flaky UI tests.
- Replacing Xcode result bundles or adding a third-party test reporter.

## Acceptance notes

- The production result-bundle wrapper extracts the supported `xcresulttool` test summary from `Tests.xcresult`.
- Verification requires `result` to equal `Passed`, `failedTests` to equal zero, `testFailures` to be empty, and `totalTestCount` to be greater than zero.
- The hosted log pipeline propagates the quality script's failure status through `tee`.
- A negative summary fixture proves recorded failures are rejected.
- A policy fixture proves the production wrapper cannot silently stop enforcing the extracted summary.
- A policy fixture proves the hosted workflow cannot remove pipeline failure propagation.
- Local and hosted full gates use the same verification path.

## Workflow

- Tier: 3.
- Rationale: The defect allows CI to misrepresent failing persistence, calendar, privacy, accessibility, or other high-risk tests as a successful authoritative gate.

## Status

Resolved.

## Priority

P1.

## Observed behavior

GitHub Actions run `40857169892` completed successfully for source revision `17b79af4b0b526eecaca34b5a91d32a0309f8499`, but the log and `Tests.xcresult` reported failures in the default-tab and primary-tab navigation tests. The repository verifier initially checked only that result-bundle directories existed.

After result-summary enforcement was added, run `40969323493` for revision `f5a10bec063fc1c273a93579c29a03910e54f668` again recorded the same two UI failures. The quality script exited unsuccessfully and retained its artifacts, but the workflow's `tee` pipeline returned success to GitHub because it did not explicitly enable pipeline failure propagation.

## Expected behavior

The authoritative quality script must fail whenever the test result bundle reports a non-passing result, any failed test, or no executed tests, regardless of the `xcodebuild` process status. The hosted job must preserve that status through logging pipelines and upload evidence from the same artifact root retained by the script.

## Reproduction or confirmation

1. Inspect GitHub Actions run `40857169892` for commit `17b79af4b0b526eecaca34b5a91d32a0309f8499`.
2. Observe `** TEST EXECUTE FAILED **` and two named UI-test failures in the log.
3. Observe that the job nevertheless concluded successfully.
4. Inspect run `40969323493` and observe that the quality script retained artifacts after the UI failures while the job again concluded successfully.

## Investigation notes

The defect is in completion verification, not app data or persistence. `Scripts/verify-result-bundles.sh` verified existence only and trusted `xcodebuild`'s status. The first correction parsed the supported `xcresulttool get test-results summary` output and independently enforced a passed result, zero failures, and at least one executed test. The hosted rerun exposed a second false-green path: the workflow piped the quality command through `tee` without explicitly propagating the script's failure status.

## Validation plan

- Add negative fixtures proving a failed summary is rejected, the production verification path remains wired, and the hosted log pipeline propagates failures.
- Run the repository policy fixture suite.
- Run the full authoritative quality gate and confirm all UI and unit tests pass.
- Obtain independent Tier 3 code review of the verifier, fixture, and final evidence.
- Push the correction and require an immutable hosted run proving truthful job status and retained failure evidence before resolving the bug.

The failure path was proven by immutable hosted run `40971487838`: the authoritative step and job both failed, and retained evidence uploaded successfully. The underlying hosted UI-test instability is tracked separately as [B-002](./B-002.md); F-002 remains open until that bug is resolved and a complete hosted gate passes.
