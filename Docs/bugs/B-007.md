# Bug B-007: Hosted quality stalls can consume artifact-upload window

## Summary

The authoritative hosted quality gate can remain stuck inside Xcode or simulator automation until GitHub cancels the entire job at its 60-minute limit. Because failure evidence uploads only after the gate returns, a job-level timeout can prevent both the complete quality log and result artifacts from being retained.

## Status

Validating.

## Priority

P1. The defect blocks trustworthy hosted completion evidence and removes the diagnostics needed to distinguish application failures from hosted simulator-service stalls.

## Objective

Bound the hosted authoritative command with a repository-owned process-group watchdog that fails a stalled gate before the job deadline, terminates its descendants, preserves the existing log and artifacts, and leaves enough workflow time for failure-evidence upload.

## Non-goals

- Retrying failed tests, simulator boots, application launches, or hosted jobs.
- Weakening assertions, suppressing failures, or accepting a timed-out run as completion evidence.
- Increasing XCTest or application-launch timeouts.
- Changing the stages or coverage of `Scripts/quality.sh`.
- Changing Cadence product behavior, persistence, accessibility, or user-facing copy.

## Workflow

- Tier: 3.
- Rationale: this changes the authoritative hosted quality and failure-evidence contract. Incorrect process termination or status propagation could mask failures, leak child processes, or lose release diagnostics.

## Acceptance notes

- CI still invokes the authoritative full `Scripts/quality.sh` command exactly once and preserves its exit status through logging.
- A repository-owned watchdog starts the command in a dedicated process group, applies one explicit hosted deadline shorter than the job timeout, sends termination to the complete group, escalates if necessary, and exits nonzero with a focused diagnostic.
- The workflow reserves enough time after the watchdog deadline for the existing failure-evidence upload step.
- Normal success and ordinary command failure retain their original exit status without delay, retry, or suppression.
- Deterministic fixtures prove success, failure propagation, timeout termination of descendants, and static rejection of missing or unsafe workflow watchdog wiring.
- Policy checks, the fast gate, and the authoritative full gate pass locally.
- Independent Tier 3 planning and complete-diff reviews find no unresolved high or critical issue.
- A hosted authoritative run must pass before resolution.

## Observed behavior

- GitHub Actions run `44510975098` attempt 1 passed policy, build, and all 115 unit tests, then recorded a 120-second lockdown-service timeout and a five-minute Xcode application-launch timeout. The remaining 27 UI tests passed, but the run failed with one infrastructure launch failure.
- Attempt 2 started the authoritative gate at 2026-11-22 12:00:03 UTC and remained in that step until GitHub cancelled the job at its 60-minute timeout. The post-gate failure-evidence step never ran, no attempt-2 artifact was created, and GitHub did not retain a finalized job log.

## Expected behavior

A hosted infrastructure stall must become a bounded, diagnosed gate failure early enough for the workflow to upload the complete log and any partial result bundles. The gate must not retry or reinterpret the failure.

## Investigation notes

- The current workflow gives `Scripts/quality.sh` the same effective deadline as the whole job, so no cleanup or upload budget remains when the command stalls.
- A shell timeout that kills only its immediate child is insufficient because Xcode, simulator, and test-runner descendants may survive and keep pipes open.
- `Scripts/quality.sh` owns the watchdog around its complete execution, preserving one direct entry point and identical bounded semantics locally and in CI. The workflow supplies the 55-minute deadline and retains a 20-minute outer reserve for termination and evidence upload.
- Attempt 2 produced no artifact beyond attempt 1's retained evidence, so its exact internal stall point cannot be recovered.

## Validation plan

- Add a repository-owned watchdog with deterministic success, ordinary failure, and timeout fixtures.
- Prove a timed-out child process group is terminated and the watchdog returns a dedicated nonzero status.
- Keep CI invoking exactly one authoritative full `Scripts/quality.sh` command while the command self-enters its process-group watchdog and the workflow tees the same retained log.
- Increase only the outer job budget enough to preserve a post-watchdog upload window; do not increase any test timeout.
- Add static policy and representative negative fixtures for watchdog invocation, deadline ordering, failure propagation, and artifact retention.
- Run `Scripts/check-policy.sh`, `Scripts/quality.sh --fast`, and `Scripts/quality.sh`.
- Require a successful immutable hosted run before resolving the bug.
