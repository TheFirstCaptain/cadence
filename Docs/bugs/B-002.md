# Bug B-002: Hosted shell UI tests fail on cold launch and adaptive navigation

## Summary

The GitHub Actions `xcode-27` runner encounters two hosted-only UI-test failures: Xcode times out during the first cold application launch, and the iPhone Duo exposes SwiftUI's adaptive navigation as a toolbar rather than the tab bar assumed by the tests. The same tests pass locally on iPhone 17.

## Status

Investigating.

## Priority

P1.

## Objective

Make the F-002 launch and navigation smoke tests deterministic on the supported hosted simulator without weakening their behavioral assertions.

## Non-goals

- Retrying failures blindly or treating a rerun as a fix.
- Increasing timeouts without identifying the runner behavior being awaited.
- Removing the hosted UI tests or relaxing the exact three-tab contract.

## Acceptance notes

- All three F-002 UI tests pass on the hosted `xcode-27` runner.
- Launch synchronization waits for the app's explicit prepared, ready, or failed state rather than an arbitrary delay.
- A regression test or deterministic guard covers the discovered failure class.
- The authoritative full gate passes locally and in GitHub Actions.

## Workflow

- Tier: 3.
- Rationale: The defect blocks the authoritative hosted quality gate and involves application bootstrap, persisted-store preparation, simulator behavior, and accessibility-driven UI automation.

## Observed behavior

Runs `40857169892`, `40969323493`, and `40971487838` recorded failures in `testAppLaunchesWithMyDaySelected` and `testNavigatesAcrossAllPrimaryTabs` on the hosted iPhone Duo simulator. The isolated startup-failure test passed. Run `40971487838` correctly failed and retained its complete evidence after B-001 was fixed.

In run `40971487838`, the launch test spent 189 seconds in Xcode's `Open com.kirkgartside.cadence` activity before failing with an application-launch timeout. The following navigation test launched successfully in 10.76 seconds, indicating a cold simulator or Xcode automation readiness problem rather than an application readiness assertion failure.

The navigation test then failed while waiting for `app.tabBars.buttons["My Goals"]`. Its retained accessibility hierarchy shows a fully prepared My Day screen and all three destinations—My Day, My Goals, and History—but exposes their container as a `Toolbar` on iPhone Duo. The test's `TabBar`-specific query therefore cannot find navigation that is present and usable.

## Expected behavior

The prepared application shell should become discoverable through its stable accessibility identifiers, expose exactly three primary tabs, and support navigation on the hosted simulator just as it does locally.

## Investigation notes

The local full gate passes all 37 tests on `platform=iOS Simulator,name=iPhone 17,OS=latest`. The hosted workflow uses `platform=iOS Simulator,name=iPhone Duo,OS=latest`.

The retained result database, activity tree, and accessibility attachment establish two independent failure classes:

1. The first UI test reaches Xcode's application-open operation but the cold hosted launch times out before test interaction begins. A later launch in the same suite succeeds promptly.
2. SwiftUI adapts the three destinations to toolbar-style navigation on iPhone Duo, while the tests assume an `XCUIElementTypeTabBar` container.

The likely correction is small to medium: make destination lookup rely on stable identifiers rather than a device-specific container role, preserve assertions for exactly three primary destinations and selection, and add deterministic hosted simulator readiness before the suite. The correction must not conceal an application launch failure with a blind retry.

## Validation plan

- Add stable, container-agnostic destination queries while retaining the exact three-destination and selected-state assertions.
- Establish simulator boot and automation readiness before the hosted UI suite, distinguishing infrastructure launch readiness from application readiness.
- Run focused UI tests against both compact tab-bar and adaptive toolbar presentation where available.
- Run the full local gate, independent Tier 3 review, and a new hosted full gate.
