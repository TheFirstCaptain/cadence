# Feature F-002B: SwiftData Schema V1

## Objective

Declare Cadence's versioned local SwiftData schema, migration plan, container factories, and idempotent built-in iIndulged category seeding.

## User value

Personal wellness records have a private, durable foundation that can evolve without rewriting their historical meaning.

## Non-goals

- Implementing repository transactions or feature workflows.
- Enabling CloudKit or any network capability.
- Designing post-V1 migrations.

## Acceptance notes

- Schema V1 contains weekly plans, planned Goal snapshots, Goal checkoffs, indulgence categories, and indulgence occurrences.
- Records use app-generated UUIDs, optional CloudKit-compatible relationships, explicit inverses where needed, and no deny deletion rules or persistence-level uniqueness constraints.
- Activity records preserve a precise instant and captured Gregorian date, canonical day key, time-zone identifier, and UTC offset.
- A declared migration plan owns Schema V1.
- Production storage is local with CloudKit explicitly disabled; tests can create isolated in-memory stores.
- Five built-in categories have fixed UUIDs and idempotent seeding.

## Clarification notes

The schema follows Decisions 002 and 003. This split changes delivery scope only, not the approved data model.
