# Feature F-002D: Three-Tab Application Shell

## Objective

Replace the generated template view with Cadence's accessible three-tab shell and focused UI smoke coverage.

## User value

Cadence launches into a predictable structure with My Day first and clear destinations for planning and History.

## Non-goals

- Implementing My Day, My Goals, or History workflows.
- Connecting placeholder screens to persistence.
- Adding a Settings tab or non-V1 navigation.

## Acceptance notes

- V1 exposes exactly My Day, My Goals, and History as primary tabs.
- Cadence opens with My Day selected.
- Each placeholder has stable visible and accessibility identifiers suitable for smoke testing.
- XCTest UI covers launch, default-tab selection, and navigation across all three tabs.
- The shell remains iPhone-only, portrait-only, and usable with Dynamic Type, VoiceOver, Reduce Motion, light/dark appearance, and one-handed reach.

Inherited F-002 finding V-005 remains applicable. The shell was visually checked at the largest accessibility Dynamic Type size in light appearance and dark increased-contrast appearance. Standard labeled tab controls expose a logical accessibility order through XCTest, no custom animation exists, and the bottom tab bar remains within one-handed reach. Spoken VoiceOver output was not manually audited; the residual risk is low because the shell uses standard SwiftUI `Tab` controls with visible text labels, but the complete manual VoiceOver audit remains part of the first functional UI feature.
