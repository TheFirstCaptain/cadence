# Feature F-002: iOS Project Foundation

## Objective

Create the native project and development foundation needed to implement Cadence safely, reproducibly, and with one shared local and CI quality contract.

## User value

A focused technical base protects personal wellness data, date correctness, accessibility, and future migrations while keeping product implementation simple.

## Non-goals

- Implementing My Day, My Goals, or History behavior.
- Enabling iCloud or CloudKit synchronization in V1.
- Supporting iPad, landscape, macOS, watchOS, widgets, or other platforms.
- Adding third-party dependencies without a separate decision.
- Creating the Xcode project before the remaining foundation decisions and required Tier 3 reviews are complete.

## Acceptance notes

- Cadence is an iPhone-only application.
- V1 supports portrait orientation only.
- The minimum deployment target is iOS 27.0.
- Development and builds use Xcode 27 or later with the iOS 27 SDK.
- The display name and product name are Cadence.
- The bundle identifier is `com.thefirstcaptain.cadence`.
- The project uses automatic signing with the user's selected Apple development team.
- Simulator and CI validation disable code signing and require no team credentials.
- One Xcode project contains `Cadence`, `CadenceTests`, and `CadenceUITests` targets plus a shared scheme; no workspace, package split, or third-party dependency is added initially.
- SwiftUI provides the application interface.
- SwiftData provides local-only persistence behind a repository/service boundary.
- Production explicitly disables SwiftData CloudKit synchronization.
- Tests can create an in-memory SwiftData store.
- Schema Version 1 is declared explicitly and future changes use versioned schemas and migration plans.
- Persisted records use app-generated UUIDs rather than persistence-level unique constraints.
- Duplicate Goal-name rules are enforced by repository logic.
- Relationships are optional, use explicit inverses where inference is unreliable, and do not use deny deletion rules.
- New persisted fields require safe defaults or optionality.
- Product dates use Gregorian civil dates in the recording time zone and fixed Monday-through-Sunday weeks; locale affects presentation only.
- Activity records preserve their precise instant plus captured Gregorian components, canonical day key, time-zone identifier, and UTC offset.
- Weekly plans own week-specific Goal snapshots joined by a stable lineage ID. Active-week edits update the whole active week, prior weeks remain unchanged, and removal closes an active interval instead of deleting historical context.
- One actor-backed SwiftData store implements focused planning, daily-tracking, and History repository protocols and returns immutable Sendable domain values.
- SwiftData models and ModelContext never cross the store boundary; view models are MainActor-isolated and Swift 6 complete concurrency checks are enabled.
- Schema Version 1 contains weekly plans, planned Goals, Goal checkoffs, indulgence categories, and indulgence occurrences.
- The five built-in indulgence categories use fixed UUIDs and idempotent seeding.
- One repository-owned quality command will run the authoritative build, tests, formatting or linting, and harness checks locally and in GitHub Actions.
- Domain, repository, calendar, and aggregation tests use Swift Testing.
- F-002 uses XCTest UI for launch, default-tab, and three-tab navigation smoke coverage. Complete workflows are added by F-003 through F-005.
- Date-sensitive tests inject a clock, Gregorian calendar, and time zone rather than reading global current time directly; deterministic fixtures can inject UUID generation.
- Formatting uses the Apple-bundled `swift format` tool, with no third-party linter initially.
- The default logical simulator destination is `platform=iOS Simulator,name=iPhone 17 Pro,OS=latest`, overridable with `CADENCE_DESTINATION`; no simulator UUID is committed.

## Affected systems

- Models/data: SwiftData Schema Version 1, identifiers, relationships, migration plan, test stores, and CloudKit compatibility.
- Views/components: iPhone portrait-only SwiftUI shell and three-tab navigation foundation.
- Services: Repository interfaces, persistence implementation, clock/calendar dependencies, and quality tooling.
- Calendar/time zone: Injectable clock, Gregorian calendar, and time zone plus storage of stable original local-date context.
- Notifications: Not enabled in V1.
- Privacy/accessibility: On-device data, no sync capability, semantic colors, Dynamic Type, VoiceOver, and Reduce Motion foundations.
- Documentation: Architecture, development plan, roadmap, requirements, acceptance tests, README, decision record, and tracker.

## Dependencies

- Xcode 27 or later and an installed iOS 27 SDK.
- An Apple development team selected in Xcode for automatic signing.

## Validation plan

- Verify the project targets iPhone and iOS 27.0, supports portrait only, and has no iCloud entitlement.
- Run `Scripts/quality.sh`: preflight; documentation/settings/entitlement checks; strict Apple formatting lint; temporary Derived Data; build-for-testing; Swift Testing; UI smoke testing; and result-bundle validation.
- Build and test on an available iOS 27 simulator with code signing disabled, using the logical default destination or `CADENCE_DESTINATION` override.
- Verify product name, display name, bundle identifier, automatic signing, and portrait-only settings.
- Verify production configuration uses local SwiftData with CloudKit explicitly disabled.
- Verify test configuration uses isolated in-memory storage.
- Add schema and transaction tests for UUID identity, stable category seeding, defaults, optional relationships, inverses, deletion behavior, normalized Goal uniqueness, active intervals, and latest-occurrence removal.
- Test local-day capture across time-zone and daylight-saving boundaries, active-week edits, prior-week immutability, and carried-forward Goal lineage.
- Add migration fixtures before any post-V1 schema ships.
- Confirm views depend on repository/service interfaces rather than direct storage mutation.
- Verify Swift Testing covers domain and repository behavior and XCTest UI covers the F-002 shell smoke scenarios only.
- Verify all date-sensitive tests use injected clock, calendar, and time-zone dependencies.
- Manually check the shell at accessibility text sizes with VoiceOver, contrast, and Reduce Motion settings before F-002 is complete.
- Run the same authoritative quality command locally and in GitHub Actions.
