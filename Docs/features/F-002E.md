# Feature F-002E: Quality and CI Contract

## Objective

Implement one repository-owned quality command and matching hosted workflow that enforce Cadence's build, test, formatting, architecture, and documentation contract.

## User value

Every future change receives consistent, credential-free validation, reducing the chance that data, accessibility, or product safeguards drift silently.

## Non-goals

- Adding third-party lint or build dependencies.
- Replacing feature-specific tests with broad policy checks.
- Requiring physical-device signing for validation.

## Acceptance notes

- `Scripts/quality.sh --fast` runs shared documentation, policy, formatting, compilation, and focused-unit stages.
- `Scripts/quality.sh` is the authoritative strict superset with clean build-for-testing, all unit and F-002 UI smoke tests, and result-bundle checks.
- Unknown modes fail and both modes share implementation rather than duplicating policy.
- Semantic checks cover project settings, owned-root membership, architectural boundaries, entitlements, tracker and link consistency, and local/CI invocation parity.
- Representative negative fixtures prove each guard rejects its drift class.
- GitHub Actions invokes the full script for pull requests, protected-branch pushes, and a weekly schedule, without signing credentials.
- The destination defaults to the approved logical iOS simulator and remains overridable with `CADENCE_DESTINATION`.

## Clarification notes

This slice implements the quality contract already approved in Decision 003. It begins before the other foundation slices with a viable local gate, remains active while they extend its coverage, and completes afterward so its membership and test policies cover the final foundation layout.

## Implementation progress

The completed implementation provides shared fast and full entry points, strict Swift formatting, documentation and tracker checks, per-target and per-configuration project-setting checks, explicit synchronized-root membership, parsed Swift architecture boundaries, local-only capability checks, forbidden unchecked-Sendable detection, credential-free simulator builds, focused unit execution in fast mode, all unit and UI execution in full mode, result-bundle verification, destination diagnostics, safe artifact handling, and retained failure logs.

The fast path now uses a separate shared scheme whose dependency graph contains only the app and unit-test targets. GitHub Actions is configured to run the authoritative full script for pull requests, pushes to `main`, weekly drift detection, and manual dispatch on the `xcode-27` runner, with an available simulator override and retained failure evidence. The local implementation is complete; one hosted run must still verify the workflow and artifact behavior before this slice moves to Done.
