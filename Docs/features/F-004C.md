# Feature F-004C: Goal Organization and Removal

## Objective

Let the user manually order weekly Goals, receive gentle manageable-list guidance, and remove a Goal while preserving earlier checkoffs and History.

## User value

The plan stays understandable and adaptable without turning flexibility into lost progress or judgment.

## Non-goals

- Imposing a hard Goal limit.
- Bulk deletion or destructive plan reset.
- Reordering My Day groups independently of My Goals.
- Building History presentation.

## Acceptance notes

- The user can manually reorder Goals in My Goals and the order persists.
- My Day preserves that order within Today and This Week.
- Beginning at 8 Goals, My Goals displays gentle guidance that a smaller list may be easier to sustain; adding more remains allowed.
- The guidance is informational, non-modal, and not presented as an error.
- Removal is initiated from the Goal editor and requires confirmation.
- Confirmation explains that earlier History remains.
- Removing an active-week Goal ends its current offering so it leaves remaining My Day views while earlier checkoffs remain available to History.
- Cancelling confirmation changes nothing.
- Failed reorder or removal restores coherent presentation and offers calm retry guidance.

## Workflow

- Tier: 3.
- Rationale: Reordering and removal mutate persistence; removal is destructive to current presentation and must preserve historical personal records.

## Findings

- High: active-week removal must reject a stale caller-supplied day and an already-ended Goal so delayed or repeated intent cannot rewrite historical truth.
- High: save, reorder, and removal need one serialized identity-safe mutation and deferred-refresh contract.
- High: every successful reorder or removal must invalidate My Day, including when the local identity changes while the write is suspended.
- Medium: reorder must reconcile the returned plan and restore the prior presentation on failure; removal failure must retain the editor for retry.
- Medium: native reorder must include named accessible move actions so VoiceOver and deterministic UI tests do not depend on drag gestures.
- Medium: manageable-list guidance is derived from the current row count and never blocks additions.
